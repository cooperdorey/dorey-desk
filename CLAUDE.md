# Notes for Claude

This repo is the Dorey Desk site (cards for OneNote). Lesson content rules (atomisation, card order,
We Do levels) live in the Lesson Creator project; this file covers the repo format.

- One file per lesson: `lessons/<year>/<course>/<NN-topic>/<code>-<slug>.html`.
- Front matter `code:` and `title:` (title may contain `$…$` maths).
- Cards use the existing `.c` / `.h` / `.b` markup with `$…$` maths (rendered at runtime
  by KaTeX as MathML). Do not paste pre-rendered MathML.
- Worked solutions go inline as `<div class="ws">…</div>` under each question, including
  on model cards. The app hides them in lesson view.
- No exercise card. Labels with "We Do" / "your turn" go right; nothing else may use those words.
- New topic: create the folder and a `_meta.json` with `{"name": "…"}`.
- A topic's Dorey's Resource Book goes in the topic folder as `drb.pdf` (other editions as
  `drb-<label>.pdf`). The LaTeX source lives in the Lesson Creator project, not here; commit the
  compiled PDF. Choosing a topic shows Lessons / DRB; `#…/<topic>/drb` is the DRB page.
- Course `_meta.json` also has `short`, `colour` and `order` (colours chosen by Coop:
  11 ADV blue, 11 STD light green, 12 STD 1 light teal, 12 STD 2 dark purple, 12 ADV navy).
- Brackets: use plain `( )`; use `\left( … \right)` only around fractions. Don't use `\big`.
  (The app draws non-fraction `\left…\right` pairs at normal size so pairs always match.)
- Before committing, run `python3 scripts/build_manifest.py`; it must report no problems.
- Classroom tools: one self-contained page per tool in `classroom/`, registered in
  `classroom/classroom.json`. The seating chart is an SVG room plan (29 desks) where an uploaded .xlsx/.csv class list is placed onto desks (the tracker's `classes.csv` is recognised by its `class` column: a class picker appears, students with `left` set are skipped, and the class code becomes the plan name; the parsed file is held in memory only; a seated student can be locked (padlock, saved with the plan, left out of the PDF), and Shuffle the rest randomly re-seats everyone unlocked, seated or in the list, across the unlocked desks) and
  exported as an A4 PDF; uploaded files are read locally, and saved plans live in the browser's `localStorage` only (listed in a left side panel), never sent anywhere. Never put student names, rosters or exported seating files in this public repo, and
  never test with real names.
  The Class Tracker (`classroom/tracker.html`, formerly the attendance tracker; tabs are grouped Overview / Attendance / Coursework / Assessment / Setup; the header class picker sets every tab's class and a tab's own picker can override it, outlined, until the header one changes) reads `classes.csv` (id, last, first, class, course, left; has names — one old `name` column is split on load), `absences.csv`
  (date, period, class, id, reason, lesson, status, notes; no names — one row per student per day per class; period and status now unused/blank) `bookwork.csv` (id, lesson, done; no names) and `nawards.csv` (id, date, number, topic, outcomes, detail, status, crt, ht, dp; status is unresolved/resolved; crt/ht/dp are the dates the parent was contacted, edited per warning on the N-awards list; no names) from a folder the user opens with the File System Access API,
  joins them in memory only, and stores nothing about students in the browser (nothing — no student data and no settings). Quick entry is a roll-call grid: a row per student with a Present column plus one column per reason; everyone starts on Present and one tap on a reason cell marks that student away with it (tap Present or another reason to change). The reason list is loaded from `classroom/reasons.json` (a `*` suffix means no catch-up owed), so it is the same on every device. Student IDs
  are permanent (`<class>-<NN>`, never reused); removing a student sets `left` (any non-blank, e.g. yes) so they drop off the
  roll and summary but keep their name on past records. Everyone is sorted by surname then first name throughout. Catch-up slips are driven by Book work, not absences: a student owes a lesson when the class has started ticking it (>=1 active student ticked) and that student's box is unticked. Tick students and print; a slip lists each owed lesson's code and title (from manifest), a OneNote/Google Classroom note and an optional deadline. The summary print sheet's heading is built from Term (1-4) and Week (5/9) dropdowns, and the attendance % prints as a colour-coded pill; a Main reason column shows the most-frequent reason only for students under 80%. The absences `status` column is unused. The N-awards tab logs non-completion warnings per student: pick one or more students + topic and two editable boxes prefill — the syllabus outcomes and a 'how to complete' blurb listing the topic's lesson codes, the DRB and an OneNote/Google Classroom note. Students are a tick-list on the left of the form (All/None buttons); each ticked student gets one warning. In the N-awards list each warning is a coloured pill: click flips Unresolved (red) / Resolved (green), right-click deletes (with confirm). The Dashboard tab (first, left of Quick entry) shows every student in a class with resolved/unresolved N-award counts a Total missed count (1-3 plain, 4-7 orange, 8+ red pill) and their owed book-work lessons in ascending order. The N-awards tab's "Print tracker sheets" button prints, for each ticked student with warnings, one A4 page modelled on the school's N-Award Tracker form (header, five letter sections; date sent, topic, contact dates (letter 1 CRT only, 2 adds HT, 3+ adds DP) and Resolved yes/no auto-filled; Supports offered = Tutorial times / Detention tick boxes left blank; no school crest). Outcomes (per course|topic-num) and classroom codes (keyed by class code, else by course key such as `year-12/maths-advanced`) come from `classroom/naward.json`. Saved to nawards.csv. The LSQ results and Assessments tabs (per class) are student×item mark grids with a percentage under each mark, a per-student average % and class summary rows; marks live in `results.csv` (class, kind `lsq`/`task`, item, id, mark; no names) and each column's settings in `resultitems.csv` (class, kind, item, name, outof, cmean, csd; the course average and SD are typed in, in marks, for tasks only; class SD is the population SD). The Book work tab builds a student×lesson tick grid for a topic, with
  the topic and lesson list read from the site's `manifest.json` (fetched at `../manifest.json`); a lesson bar reads the taught date(s) for a lesson from the absences (the dates that lesson is recorded against) and ticks present / unticks absent for that column. `course` links a class to a
  manifest course (key `<year-id>/<course-id>`, e.g. year-12/maths-advanced), so the Book work topic list filters to that course. Test with made-up names only.
  New top-level site folders must also be added to the `cp -r` line in `.github/workflows/pages.yml`.
- Generators: one page per generator in `generators/`, registered in
  `generators/generators.json`. The question bank (`gen` functions, topics, lessons and each
  lesson's `marks`) lives in `generators/engine.js`, shared by the question generator, the
  LSQ generator (`lsq.html`, 2-page A4 quiz, PDF via the vendored jsPDF + html-to-image) and the
  homework generator (`homework.html`, two-page (double-sided) HSC-style Question 1 with parts (a), (b)… sorted
  by marks, at most two 1-mark parts, same PDF approach). A lesson's `marks` decides where its
  questions sit on the homework sheet, so set it to the HSC value. New lessons must also be APPENDED to the end of `CODE_ORDER`
  in engine.js (never reorder): the faint sheet code printed on LSQ and homework pages records the ticked
  lessons as bits in that order, and the build fails if a lesson is missing. The All / Yr 11 / Yr 12 / Clear buttons above each topic list come from
  `generators/picker.js` (load it after the page's own script); a topic's year is read from its `course`. They use the site's vendored KaTeX (MathML output), no CDNs.
  `generators/hsc-bank.js` (past HSC questions tagged to lessons; each entry has the paper wording and an
  optional `gen(R)` with new numbers) and `generators/week.js` (HSC draw modes, homework set builder, linked LSQ,
  sheet codes) load after engine.js on both pages. Run `node scripts/check_generators.js --all` before committing.
  Sheet codes: the homework code also records the lessons that ended up on the sheet; a linked LSQ's code is
  `homeworkCode~…`. Codes are read back in the on-screen lesson order, so keep engine.js lesson order stable.
  Question text from HSC papers is cited by year and question number; omit questions that need a diagram.
  In the question generator, test every generator function on many seeds before committing
  (all maths must parse in KaTeX; no `NaN`, `undefined`, `+ -` or `1x`).
- Standard 1 LSQ (`generators/lsq-std1.html`): a copy of the LSQ page with its own bank, `generators/std1-bank.js`
  (global `S1`; text-only questions for Std 1 topics 1 to 3; borrows only the RNG and fraction helpers from engine.js).
  Its `CODE_ORDER` is append-only too (checked by `build_manifest.py`). Sheet codes end `.s1.<lessons>` so the Advanced
  pages reject them. Money inside maths is written `\$`. Triangle questions (topic 3, except 3.01 true/false, 3.06 angle conversions and 3.09) carry an inline-SVG diagram in `fig` (helpers `triFig`, `rectFig`, `eyeFig`, `bearFig` in std1-bank.js, no `$` inside), shown beside the question and checked by `check_std1.js`. Quizzes are capped at 20 minutes / 20 marks (diagrams make questions tall). Run `node scripts/check_std1.js` before committing.
- Tutorial generator (`generators/tutorial.html`): hard, unfamiliar questions for a 20, 25 or 30 minute tutorial. Its bank is
  `generators/tutorial-bank.js` (loads after engine.js; independent of lesson ids and `CODE_ORDER`). Each template has a topic id
  from `TOPICS`, a (now ignored) minutes value, level (2 Hard, 3 Very hard), a hint and `gen(R)`, which must return a `chk()` that tests the printed
  answer numerically. Marks per part live in `TUT_MARKS` (from similar HSC parts); minutes are 1.8 per mark. `buildTutorial` fills the time target within 2 minutes. Run `node scripts/check_tutorial.js` before committing.
  The page also builds A4 pages (student sheet with working space sized by minutes and a Working space setting; teacher answers with hints)
  and downloads them as PDFs with the vendored jsPDF + html-to-image, as the LSQ does.
- Admin (start-page tile, `admin/`): one self-contained page per tool, registered in `admin/admin.json`; `admin` is in the `cp -r` line of `pages.yml` (and `admin/*.html` in its cache-busting `sed`). The first tool is **Attendance** (`admin/attendance.html`, logic in `admin/attendance-core.js`, which is plain JS that `scripts/check_attendance.js` tests on made-up data: run `node scripts/check_attendance.js` before committing). Like the Class Tracker it opens a folder with the File System Access API (or Open files…), keeps everything in memory, stores nothing about students in the browser, and **no student names, SRNs, exports or rosters may ever go in this public repo** (test with made-up names only).
  The folder is a calendar-year folder: school-system exports named `T<term>W<week>.xlsx` (main term-to-date export, in the folder or a `T1`–`T4` subfolder) and `T<term>W<week>_short.xlsx` (the "<=120min" short-partials export), plus rosters `yr11.csv` and `yr12.csv` (columns `Student Name` as "Last, First - SRN", and `Removed`). The report type is read from the column headers, not the filename; the rolling-attendance export is ignored. Students are joined across files by the SRN after the last dash, never by row order. Exports are term-to-date, so a term's last week is its final file; terms are added by summing days (never averaging rates), and the weekly early warning is this Friday's file minus the one two weeks earlier (negative differences clamped to 0).
  The school `Attendance Rate` is (enrolled days − whole days absent − 0.5 × partial absences over 120 minutes) ÷ enrolled days; partials of 120 minutes or less are not in it. Bands are 90/95/100% (nested); tiers are 80 ≤ rate < 90, 50 ≤ rate < 80, rate < 50, with integer-exact comparisons and percentages truncated (never rounded up across a line). The unexplained list is whole-day unexplained ÷ enrolled days ≥ 30%, with a minimum enrolled days. Early-warning rules (all adjustable on the page): sudden drop (≥15 points below the student's own earlier rate and ≥3 days lost), fell out of the regular band (≥90% before, ≤80% in the window), unexplained cluster (≥2 unexplained whole days in the window), short-partial spike (≥300 minutes); the table also shows how many Fridays in a row a student has been flagged. A student on neither roster appears under Setup → Not on a list (shown in All, left out of the Year 11 / Year 12 figures) with Year 11 / Year 12 buttons that write the roster CSV; Remove sets `Removed`, which takes the student off every list and count (the "Include removed students" box brings them back) while their data stays in the files; Restore undoes it. Keep the page minimalist: no explanatory blurbs, only live status messages, and no inner scroll boxes.
